# Browser Testbench 0.7.0

Version 0.7.0 unifies video and audio recording through OBS Studio and adds per-device recording settings.

## Recording with OBS

OBS now records desktop browsers, Android emulators and devices, and iOS simulators and USB devices. The previous
recording backends have been removed. Browser automation and screenshots still work without OBS.

On the computer running Browser Testbench:

1. Install OBS Studio and FFmpeg, including `ffprobe`.
2. Open OBS, finish its first-run assistant, and enable the password-protected server under
   **Tools → WebSocket Server Settings**.
3. Leave OBS running and select **Check again** on the Testbench Overview page.
4. Open **Documentation → Recording** for the platform-specific instructions.

Testbench reads the local OBS connection settings automatically. Custom installations can use `OBS_URL` and
`OBS_PASSWORD` in the host environment. Do not put credentials in project files.

Desktop and simulator recordings use visible windows and system audio. Keep the target window visible and silence
unrelated applications and notifications. Physical Android capture additionally needs Android 11+ and scrcpy 3+.
Physical iPhone capture requires macOS and a USB connection. Linux recording requires X11.

Only one OBS recording can run on a Testbench computer. Stop existing OBS recordings, streaming, replay buffer,
and virtual camera output before starting a Testbench recording. Testbench restores the previous OBS workspace
when its recording session closes.

## Per-device recording settings

Use the gear next to a device name on **Overview** or **Test targets** to open its recording settings:

- **Audio synchronization offset:** positive milliseconds delay audio; negative values advance audio relative to video.
- **iPhone capture source:** select the connected USB device used by OBS.

Settings are stored on the Testbench computer and applied to the next recording. Android emulator settings use the
AVD identity, so a changed runtime serial does not discard calibration. Remote clients need administrative access
to change these settings.

## API compatibility and migration

The public session and explicit recording APIs remain source-compatible. Upgrade clients and the server together
to 0.7.0; Testbench requires matching versions.

```ts
import { RemoteTestbench } from 'browser-testbench/client';

const testbench = new RemoteTestbench();
const browser = await testbench.open({
    target: 'chrome',
    url: 'https://example.com',
    require: { recording: { viewport: true } },
});

try {
    await browser.recording.start({ outputPath: './recording.mp4', scope: 'viewport' });
    // Run the browser workflow here.
    await browser.recording.stop();
} finally {
    await browser.close();
}
```

Request recording when opening a physical iPhone session: USB capture must be prepared before Safari automation
connects. Close the session when finished to release its capture resources.

Recording does not bypass browser autoplay restrictions. Safari and iOS Safari still do not advertise
`mediaPlayback.autoplay`. Audio may require a native user gesture; a WebDriver element click is not guaranteed to
unlock an `AudioContext`. Use the native `session.tap(x, y)` gesture when testing interactive media on iOS.

## Reliability and maintenance

- Viewport cropping excludes Safari's translucent browser bars.
- Android emulator capture finds the window by its AVD name.
- iOS Safari gets a 20-second Web Inspector discovery budget, while custom `appium:webviewConnectTimeout` values
  remain supported. The session proceeds as soon as the connection is ready.
- Detached Chrome elements are retried once with a fresh reference.
- Shutdown closes sessions before removing recording and asset directories.
- Recording services and settings live in one module. Diagnostics, permissions, and recording artifacts have
  separate owners. UI styles and documentation are organized by component.

## Verification scope

Local recording checks covered Chrome, Edge, Firefox, an Android emulator and USB device, an iOS simulator, and a
USB iPhone on macOS. Flash/beep probes checked the recorded video and audio together. Audio offsets are specific to
the tested device and capture path; these results are not universal calibration presets.

Automated CI checks run on macOS, Windows, and Linux. They do not replace native OBS capture testing on each host OS;
Windows and Linux OBS recording were not hardware-validated for this release.
