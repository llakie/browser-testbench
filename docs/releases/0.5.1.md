# Browser Testbench 0.5.1

Version 0.5.1 stabilizes Android Chrome startup and permission handling for automated camera and recording workflows.

## Android Chrome startup

Android Chrome can restore its tab overview or a previously open tab when Appium attaches. Browser Testbench now navigates to `about:blank` immediately after the Android browser session starts, before it grants origin permissions and opens the requested URL. The requested page therefore becomes the active tab deterministically.

Automatic Chrome translation UI is disabled for Android automation sessions. This prevents an infobar from changing the browser viewport during screenshots or recordings.

## Redirected permissions

An application URL can redirect between equivalent origins, for example from an apex domain to its `www` host. Browser Testbench now compares the requested and final origins after navigation. For same-scheme, same-port apex/`www` redirects, requested browser permissions are granted to the final origin as well, and that page is reloaded once so it can request camera, microphone, geolocation, or notification access with the permission already in place. Permissions are not propagated to unrelated redirect targets.

The session metadata lists both the originally requested permission and any confirmed redirected-origin permission. All affected origins are restored during session cleanup.

## Compatibility

There are no API or configuration changes. Clients and servers must still use the same Browser Testbench version.
