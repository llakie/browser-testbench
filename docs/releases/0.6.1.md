# Browser Testbench 0.6.1

Version 0.6.1 adds deterministic media autoplay for automated audio and video workflows.

## Automated media playback

Chrome, Edge, Firefox, and Android Chrome sessions now start with their browser-native autoplay policy configured for
automation. Their target metadata advertises this as `mediaPlayback.autoplay`, so clients can reject an incompatible
target before starting a workflow:

```ts
await testbench.open({
    target: 'chrome',
    url: 'https://example.com',
    require: { mediaPlayback: { autoplay: true } },
});
```

Safari and Safari on iOS do not advertise this capability because Browser Testbench cannot guarantee gesture-free
media playback on those targets.

Custom Chrome, Edge, Firefox, and Android browser options are merged with the required autoplay settings instead of
replacing them.

## Development tooling

The repository now uses the same four-space Prettier and ESLint control-flow conventions as Browser Testbench
Director. CI verifies formatting, braces, guard clauses, and spacing around control structures.

## Compatibility

The existing session API remains source-compatible. The capability response contains the new
`mediaPlayback.autoplay` field. Clients and servers must continue to use the same Browser Testbench version.
