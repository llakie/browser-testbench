# Browser Testbench 0.5.0

Version 0.5.0 adds deterministic device recording, session assets, secure Android loopback origins, declarative browser permissions, and static camera images.

## Requirements

- Node.js 22.12 or Node.js 24 and newer
- FFmpeg and ffprobe on `PATH` for recordings and mobile screenshots that contain only the visible web page area
- Android SDK Platform Tools for Android targets
- Appium drivers shown by the setup UI

The capability response reports unavailable recording or viewport capture before a session starts when media tooling is missing.

## Capabilities

Use `target.require()` before expensive work and repeat mandatory requirements through `open({ require })` when the server must enforce them:

```ts
const testbench = new RemoteTestbench();
const target = await testbench.target("chrome-android-browser-testbench-api-36");

target.require({
  localOrigins: { reverse: true },
  permissions: { native: ["camera"], origin: ["camera"] },
  mediaInjection: { cameraImage: true },
  recording: { viewport: true, geometry: true, marks: true },
});
```

Capabilities separate server limits from target features. Current limits are 1 MiB per JSON request, 50 MiB per asset, and 100 MiB of assets per session.

## Android camera session

Assets accept buffers and paths relative to the calling process:

```ts
const card = await testbench.assets.upload("./assets/de/de/card.jpg", {
  contentType: "image/jpeg",
});

const session = await testbench.open({
  target: target.id,
  url: "http://127.0.0.1:4301",
  localOrigins: "reverse",
  permissions: [{ name: "camera", origin: "http://127.0.0.1:4301" }],
  media: { camera: { facing: "back", source: card } },
});
```

`localOrigins: "reverse"` is the default for Android loopback URLs. It creates a session-owned `adb reverse` mapping and keeps the browser origin on `localhost` or `127.0.0.1`. The insecure emulator host fallback is available only through `localOrigins: "emulator-host"`.

The server discovers the active Android browser package, grants its native camera or microphone permission, grants the requested browser-origin permission before navigation, and restores the previous state during cleanup.

## Recording and time

```ts
await session.recording.start({ outputPath: "./export/raw.mp4", scope: "viewport" });
await session.mark("story.start");
await session.waitForElement("[data-testid=price-result]", { timeoutMs: 90_000, signal });
await session.mark("price.visible");
const recording = await session.recording.stop();
await session.close();
```

`stop()` stops the native recorder before browser teardown, verifies the MP4 with ffprobe, transfers it atomically, and checks its byte size and SHA-256. Its result includes codec, container, dimensions, duration, time base, average frame rate, VFR/CFR mode, ordered marks, and geometry samples.

Geometry uses left/top-inclusive and right/bottom-exclusive rectangles. `viewportInVideo` is expressed in video pixels. CSS viewport dimensions and safe-area values use CSS pixels. Browser and system inset subdivisions remain `null` when the platform cannot determine them reliably.

## Screenshots

Use `captureScreenshot()` for explicit semantics:

```ts
const image = await session.captureScreenshot({ scope: "viewport" });
```

Supported scopes are reported per target: `screen`, `viewport`, `fullPage`, and `element`. Results contain dimensions and screen/viewport mappings. Unsupported requests fail with `SCREENSHOT_SCOPE_UNSUPPORTED`. The existing `screenshotBase64()` remains compatible and retains its driver-dependent 0.4 behavior.

## Timeouts, abort, leases, and cleanup

Waits and navigation accept `{ timeoutMs, signal }`. The transport timeout is the operation timeout plus a five-second network grace period. Caller aborts use `OPERATION_ABORTED`; elapsed operation timeouts use `WAIT_TIMEOUT`.

Sessions have a 90-second server lease and a 30-second client heartbeat by default. Target locks persist owner, session, PID, and process-start identity. Cleanup failures quarantine a serial target until a retry proves cleanup complete. `close()` and `recording.stop()` are idempotent.

## Errors and diagnostics

New and changed failures are `TestbenchError` instances with `code`, `message`, `operation`, optional `sessionId`, and serializable `details`. The release defines `TARGET_BUSY`, `SESSION_LEASE_EXPIRED`, `STALE_ELEMENT`, `PAYLOAD_TOO_LARGE`, `ASSET_LIMIT_EXCEEDED`, `WAIT_TIMEOUT`, `OPERATION_ABORTED`, `LOCAL_ORIGIN_UNAVAILABLE`, permission/media/recording errors, `SCREENSHOT_SCOPE_UNSUPPORTED`, and `CAPABILITY_UNAVAILABLE`.

`session.diagnosticBundle()` returns redacted session metadata, operations, marks, DOM, viewport screenshot, browser events, permissions, recording state, and cleanup state. Authorization and cookie headers are never returned verbatim.
