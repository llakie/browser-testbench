# Migration von Browser Testbench 0.4.x

[English](./0.5.0-migration.md)

## Breaking Changes

Version 0.5.0 enthält keine beabsichtigten Breaking Changes auf Quellcodeebene. Bestehende Konstruktoren, `open()`, `videoPath`, positionale Wait-Timeouts, `screenshotBase64()` und `screenshot(path, fullPage)` bleiben unterstützt.

Ein vorhandener 0.4.x-Client kann ohne Änderungen an seinen Aufrufen aktualisiert werden. Prüfe die folgenden Verhaltensänderungen, wenn dein Projekt Android-Loopback-URLs auswertet, Fehlermeldungen parst, große JSON-Payloads sendet oder erwartet, dass ein Target nach fehlgeschlagenem Cleanup sofort freigegeben wird.

## Bevorzugte APIs in 0.5.0

| Aufruf in 0.4.x                                   | Bevorzugter Aufruf in 0.5.0                                               |
| ------------------------------------------------- | ------------------------------------------------------------------------- |
| `open({ target, videoPath })`                     | `open({ target })`, dann `session.recording.start({ outputPath, scope })` |
| `waitForElement(selector, 90_000)`                | `waitForElement(selector, { timeoutMs: 90_000, signal })`                 |
| große Base64-Argumente in `evaluate()`            | `testbench.assets.upload(pathOrBuffer)`                                   |
| rohe `appium:avdArgs`-Kameraargumente             | `media: { camera: { facing: "back", source: asset } }`                    |
| `appium:autoGrantPermissions` plus eigenes ADB    | deklarative `permissions` in `open()`                                     |
| Emulator-URL wird auf `10.0.2.2` umgeschrieben    | `localOrigins: "reverse"` mit unveränderter Loopback-URL                  |
| `screenshotBase64()` für geometriesensible Arbeit | `captureScreenshot({ scope })`                                            |

`videoPath` verwendet intern denselben Ablauf, der die Aufnahme vor dem Browser beendet. `appium:autoGrantPermissions: true` bleibt für Android-Browsersessions gültig und wird bei vorhandener Start-URL für Kamera und Mikrofon auf die neue native und Origin-bezogene Berechtigungsimplementierung abgebildet.

## Beobachtbare Verhaltensänderungen

- Android-Emulator-Loopback-URLs bleiben standardmäßig auf `127.0.0.1` oder `localhost`. Verwende `localOrigins: "emulator-host"` nur ausdrücklich, wenn die Anwendung das frühere Verhalten mit `10.0.2.2` benötigt. Der daraus entstehende Origin ist möglicherweise kein Secure Context.
- Fehler des 0.5.0-Servers sind `TestbenchError`-Instanzen mit stabilen Feldern `code`, `operation` und `details`. Code, der vollständige Fehlermeldungen prüft, sollte stattdessen `code` prüfen.
- JSON-Anfragen über 1 MiB schlagen jetzt mit `PAYLOAD_TOO_LARGE` fehl. Übertrage Binärdaten mit `testbench.assets.upload()`.
- Selektoraktionen werden ausschließlich nach einem Stale-Element-Treiberfehler genau einmal wiederholt. Andere Klickfehler, einschließlich überdeckter oder deaktivierter Elemente, werden weiterhin sofort zurückgegeben.
- Ein fehlgeschlagener Cleanup hält ein serielles Target in Quarantäne, statt ein noch verwendetes Gerät für eine weitere Session freizugeben.
- Sessions haben eine Lease von 90 Sekunden. Der 0.5.0-Client verlängert sie automatisch; eigene REST-Clients müssen sie vor Ablauf mit `POST /v1/sessions/:id/lease` erneuern.
- Mobile Aufnahmen enden vor dem Browser-Teardown. Das letzte Bild enthält daher keinen Launcher oder Home-Screen mehr.
- Viewport-Aufnahmen und strukturierte mobile Screenshots benötigen `ffmpeg` und `ffprobe` auf dem Testbench-Host. Die Capability-Erkennung meldet ihr Fehlen vor dem Session-Start.

## Upgrade-Checkliste

1. Aktualisiere Client und Testbench-Server gemeinsam; ihre Versionen müssen übereinstimmen.
2. Behalte vorhandene 0.4.x-Aufrufe bei oder übernimm die bevorzugten APIs aus der Tabelle schrittweise.
3. Ersetze Prüfungen vollständiger Fehlertexte durch Prüfungen von `TestbenchError.code`.
4. Prüfe Android-Tests, die `10.0.2.2` erwarten, und wähle `localOrigins: "reverse"` oder ausdrücklich den Fallback `"emulator-host"`.
5. Verschiebe binäre `evaluate()`-Payloads über 1 MiB in die Asset-API.
6. Installiere `ffmpeg` und `ffprobe`, wenn du Viewport-Aufnahmen oder strukturierte mobile Screenshots verwendest.
